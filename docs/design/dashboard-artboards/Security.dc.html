Keys stay in the vault

Security

Two doors, one vault. A key you type in a form goes straight to the vault. A key found in your code is swapped for a placeholder before any AI sees it.

1. What the AI sees
const key = "__FF_SECRET_1__";
Only a placeholder. The real key never leaves your machine.
2. What the vault holds
__FF_SECRET_1__ = encrypted (Fernet) shown as "configured"
Write-only. No page or API can read a key back.
3. What your code gets back
const key = process.env.STRIPE_KEY;
Restored as an environment variable. Verified and scanned again first.

Seven guards

Scan
Code is read as a syntax tree, with pattern matching as a backup, to find keys.
Redact
Each key becomes a placeholder before any model call.
Verify
The edited code must still parse and keep every placeholder.
Re-scan
The result is scanned again so no new key sneaks in.
Restore
Placeholders become env vars by default, never hard-coded keys.
Log filter
Logs and run events are redacted before they are stored.
Gates
Payments and code changes always wait for your approval.

Six privacy rules

1. Keys are write-only and show as "configured". 2. Nothing leaves your machine except calls you set up. 3. Only connector names and tool lists reach the Planner, never keys. 4. Stored runs are redacted. 5. You can delete a connector and its key at any time. 6. No telemetry.

Honest limits

Scanning finds known key shapes. An unusual custom secret could be missed, so name it in the form to protect it. A model you connect still sees the task text you send it. Local use only for now. Running it on a server needs its own hardening.
