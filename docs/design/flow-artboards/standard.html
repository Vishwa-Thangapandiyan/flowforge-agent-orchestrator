The MCP Map

A proposal for a standard way to send someone your app's MCP architecture: what it calls, in what order, how long each call takes, and what is slow. Lanes are kinds, time runs left to right, and every call is a bar as long as it takes. It prints in black and white, and it travels as an image, as Mermaid that GitHub renders, or as the Flow JSON behind it, which cites every block's file and line.

The rules

  1. Lanes are kinds. Decisions on top, then LLMs, MCP servers, APIs and local programs, always in that order, so any two maps compare at a glance.
  2. Time runs left to right. A call starts when its inputs are ready; its bar is as long as the call takes. Long bars are what make an app slow.
  3. One shape per kind, so it reads without colour: a ring for an LLM, a hexagon for an MCP server, a square for an API, a triangle for a local program, a diamond for a decision.
  4. The thick line is the critical path. Dashed means reached through another server. A dashed bar is an estimate, not a measurement.
  5. Marks: a dot is health (teal up, amber needs a look, coral down), ✎ writes something, ↻ repeats in a loop.
  6. Every block has a source. The Flow JSON behind the map gives each one's file and line, so anyone can check it against the code.
