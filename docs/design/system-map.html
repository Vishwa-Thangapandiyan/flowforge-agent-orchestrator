A regex finds key-shaped strings. The AST then confirms where each one sits in the code, even inside a function or config object.

  


  
The guards, in the order they run

  

    
1 · FindAST and regex locate every key-shaped value in the code.

    
2 · RedactEach becomes <REDACTED_STRIPE_KEY_1>. The real value goes to the vault.

    
3 · LLM editsIt sees names and placeholders only, never a value.

    
4 · VerifyEvery placeholder must come back exactly once. A missing or extra one stops the run.

    
5 · ScanThe output is scanned for key-shaped strings, so an invented key is caught.

    
6 · RestoreDefault is process.env.STRIPE_SECRET_KEY with the value in .env. Literal only for local runs.

    
7 · ApproveYou review the diff and tests on a branch. Nothing lands on main by itself.

  


  
Privacy rules for the whole app

  

    
Placeholders everywhereLogs, run history and the dashboard never show a real value. Keys display as "configured".

    
Vault, not gitThe vault is encrypted on disk. .env is git-ignored.

    
Local firstData lives in SQLite on your machine. No cloud account is needed to start.

    
One doorEvery app talks through FlowForge core, so keys, cache and approvals are enforced in one place.

    
Least accessEach connector gets only its own key. Risky actions, like payments or deploys, wait for your approval.

    
Safe cacheOnly deterministic calls are cached, and cached text is stored redacted.

  


  

    Honest limits
    
    
      
  • Redaction hides keys. The rest of the code still goes to the LLM you picked.
    • 
      
  • Private code or customer data in the code? Use a local model like Ollama on your ROG, so nothing leaves your network.
    • 
      
  • Regex and AST catch known key shapes. A key with an unusual format needs a custom pattern, added in the connector form.
